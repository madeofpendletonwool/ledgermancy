# Screenshots

Drop the captures here. The README and docs reference these exact filenames —
see the [README feature grid](../index.md) and each feature page.

## Filenames

| File | What to capture |
| --- | --- |
| `hero.png` | Wide cinematic Dashboard shot for the README top. ~1600px. |
| `dashboard.png` | Dashboard, full viewport, logged in with data. |
| `spending.png` | Spending page, a month selected, category bars + recurring visible. |
| `net-worth.png` | Net worth trend + breakdown, ideally with holdings/debt. |
| `report.png` | Financial Summary, scrolled to the cash-flow section. |
| `insights.png` | Insights feed with several cards. |
| `assistant.png` | Assistant mid-conversation (sandbox or real data, no secrets). |
| `budget-goals.png` | Budgets page with at least one active budget + Safe-to-spend. |
| `alerts.png` | Alerts page with a fired alert event. |
| `transactions.png` | Transactions with filters applied (date + account + category). |
| `categories.png` | Categories page showing custom + built-in. |
| `accounts.png` | Accounts page with linked institutions + history spans. |
| `household.png` | Settings → Household tab with members + invites. |
| `security-2fa.png` | Settings → Security, 2FA enrolled, sessions list. |

## Tips

- Capture at **1600px wide** where possible; the README hero can be wider.
- The app is **dark-only** — screenshots should be too.
- Hide anything you don't want public. Use sandbox data if in doubt
  (`user_good` / `pass_good`).
- Name the files exactly as above; the markdown already points at them.

Until files land, the image links render as broken images — that's expected and
fine for a draft.
