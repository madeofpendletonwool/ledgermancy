Wave 6 plan · assistant → advisor · docs 24 + 31 + 32 + 33

The Ledgermancy Advisor

From a reactive Q&A terminal over transactions into a full financial advisor — one that opens with a briefing, surfaces ranked options for spare cash, splits a lump or monthly surplus across Roth / 529 / brokerage / debt / emergency fund with per-bucket projections, and tells you — grounded in Monte Carlo likelihoods — which plan most reliably meets your goals. Every engine it needs already exists in the backend. The work is exposure, surface, the proactive ranker, and the allocation planner.

The thesis. The assistant today answers past-tense questions about transactions. A real advisor comes prepared, says “you have $X — here’s how to split it across your Roth, 529, and brokerage, and here’s what each path does to your goals,” and works across every horizon from next Tuesday to retirement. This wave turns the Assistant route into the Advisor route, exposes ~17 existing deterministic engines as chat tools, ships doc 24’s proactive ranker, and builds a multi-bucket allocation planner with a Monte Carlo likelihood layer. No new math is invented — FIRE, debt, goal, safe-to-spend, returns, obligations, and contribution-limit engines all already exist. The one line held throughout: the app presents computed tradeoffs, and where the math is unambiguous it may note it; it never substitutes opinion for arithmetic.

This is the visual companion to the wave-6 plan docs: 24 proactive engine 31 advisor surface 32 allocation planner 33 likelihood layer.

When the math is unambiguous, the advisor may note it. “Paying the 22% card returns a guaranteed 22%; investing at an assumed 5% does not” is a computation, not advice. 13 Principles

Six rules, drawn from chat_handlers.go and docs 24/28, extended across the whole surface. These stop a feature that looks like advice from becoming advice.

Deterministic computes, AI narrates

Every figure computed in exact decimal server-side. The model receives finished numbers and writes prose. It never invents an option, never reorders, never computes. Extend the existing prompt; don’t write a new one.

Show the arithmetic

Every number expandable into its components: the slack pieces, the APR, the term, the assumption, the distribution basis. Separates the feature from a horoscope.

Works with no AI key

Every advisor feature renders with ErrDisabled. Engines produce results; AI only phrases. A blank AI_API_KEY degrades to plain deterministic lists — never an error screen.

Scope invariant on every query

household_id AND (user_id OR is_shared) on every new tool. A forgotten scope leaks a spouse’s full position. Test per tool.

Surfaces appear only when there’s something to say

An advisor that fires on $12 of slack trains the user to ignore it. Options, insights, and push all clear a meaningful threshold. Silence beats noise.

Two surfaces must agree

If Budgets shows $487 of safe-to-spend and Advisor shows $512, trust in both is destroyed. Reuse the same engines; assert agreement at exact decimal.

14 FAQ

Is this giving me financial advice?

No. Computed tradeoffs, not recommendations. The math-grounded stance lets the advisor note an unambiguous spread, and doc 33’s guardrail lets the AI name a top pick in terms of the computed likelihoods — but the rule is documented and deterministic. Security-level and product recommendations are permanently out (regulated advice).

How does the AI pick the “top” plan without guessing?

The guardrail rule is written down, not vibes: “prefer the plan that meets all stated goals with the highest success rate, subject to the user’s drawdown floor; break ties by lower volatility.” The AI receives each plan’s computed percentiles, success rate, and goal-fit, plus the rule, and explains the pick in those terms. Same inputs → same pick → same explanation.

Will it work without an AI key?

Yes. Every engine is deterministic; AI only phrases. With AI_API_KEY blank, the briefing, options, allocator, and likelihoods all render as plain lists/figures with no narration and no error. Same discipline as the current assistant.

How is this different from doc 24?

Doc 24 is the single-pick proactive engine (one slack amount → ranked single options). Doc 31 is the surface (the page + chat exposure). Doc 32 is the multi-bucket allocator (split across buckets with caps + projections). Doc 33 is the likelihood layer (Monte Carlo + guardrail AI + plan tracking). They compose.

Do I need docs 23/26/27?

Yes — that’s why they’re wave 5 and the advisor is wave 6. Doc 23 makes contribution headroom real; 26 keeps asset values from drifting; 27 makes long-horizon dollars honest. The allocator and likelihood layers inherit their inputs.

What stops the model inventing numbers?

The system prompt in chat_handlers.go already forbids it: every figure from a tool call, the model never does arithmetic. New tools inherit those rules verbatim. StringFixed(2) results make a quoted figure trivially auditable — it matches a tool output or it doesn’t.

Can my spouse see my plans/threads?

Household-scoped, following the same shared/private rules as accounts. A shared-finances plan is visible; a private-account question is not. The scope invariant on every query is what enforces this — and why a leak there is a critical-severity risk.
